# OneDish README rewrite design

## Goal

Turn the README into a concise English project page that works for hackathon judges first and developers second.

## Structure

1. New Devpost thumbnail as the hero.
2. The user problem and the one-decision product promise.
3. Direct links to the live demo and 2:08 demo video.
4. A short, concrete product flow.
5. The boundary between optional OpenAI interpretation and deterministic selection.
6. Architecture, local setup, privacy, honest demo limits, tests, and stack.

## Voice and constraints

- Natural founder voice with short paragraphs and concrete claims.
- Keep allergen guarantees, local storage, fictional menu provenance, optional provider behavior, and ordering limits accurate.
- Remove process-report language and inflated promotional copy.
- Preserve executable commands and verified repository links.
